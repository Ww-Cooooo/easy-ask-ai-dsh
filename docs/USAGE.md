# 使用说明

[返回项目首页](../README.md)

## 修改已有成果


1. 在工作区原聊天里提出想法或反馈，例如“请看 registration-original.md，这个报名页不够正式”。
2. 点击“查看本次对话”。先看到按聊天顺序排列的讨论节点，当前问题突出显示，长对话可通过编号索引定位。普通回复默认合并收起，点击即可展开；“当前”也能展开并定位最新普通回复。点节点再看问题、你的回答和 AI 理解，完整原话与选项按需展开。短标题只用于定位，不替代完整条件。
3. 需要澄清时，AI 阅读原作，一次问一个具体问题。问号和虚线表示 AI 猜测，回答保留你的原话；勾号区分“已确认方案”和“已确认效果”，点开可看对应范围或文件，以及确认原话。新回答会连到对应节点，其他节点保持原位；支持系统减少动态效果设置。问清后打开“查看修改方案”，核对修改、保留、排除、交付和验收。在原聊天继续回答或补充，侧栏自动更新，报告会形成新版。
4. 看过当前方案后，可以明确回复“就按这个方案改”。插件核对真实聊天记录与此前展示的版本，不需要手输校验码。回答问题、单独说“好”或附带新条件，都不会自动认可整份方案。
5. 模型在同一聊天执行已认可范围，登记实际产物及逐项证据；你查看成果后再评价效果。回答当前成果核对时，“都对了”“这版没问题了”等明确评价可以记为效果认可；插件会核对原话和此前展示的对应成果，不要求照抄固定口令。引用、部分满意、附带修改条件、回答别的问题或多份成果指向不明时，不会自动视为全部通过。也可以在详情中逐份评价。

## 原作、版本与结果

“原作、版本与结果”展开完整详情：默认原作与报告并排，也可切换到“来源随条目”；保留来源关系、报告编辑、版本差异、结果证据和导出。切换聊天时，各自的记录独立恢复。

侧栏顶部用五步标明整体进度：**问清需求 → 核对方案 → 执行修改 → 查看成果 → 完成**，下面说明现在该谁行动。方案已确认、执行尚未开始、AI 正在执行、等你查看成果分别显示；只有对应成果取得真实的本人认可，才显示完成。点开历史节点不会改变整体进度，普通收尾回复也不会让任务重新变成待回答。补充新的修改意见后，进度会回到需要继续处理的阶段，旧的确认记录仍保留。运行状态来自 Harness 的实时状态；连接不可用时明确显示未知，侧栏关闭后停止订阅。

拖动右侧栏左边缘的竖向手柄即可调宽。窄栏中，节点概览和详情上下排列；空间足够时，展开的详情会与概览并排，当前选中节点保持不变。正文和操作区随可用宽度换行，窗口缩小时由 Harness 保留聊天区所需空间。

节点用蓝色 **Get Clear**、紫色 **Prompt Ready** 标明本轮实际参与的插件流程；普通回复为灰色。流程颜色与确认状态分开：琥珀色问号和虚线表示猜测，绿色勾号表示已核验的本人确认。点开“来源依据”可查看对应操作。单纯读取插件记录不会被算作一次澄清；“已读 Skill”只说明模型读取过原 Skill 的入口或参考，不表示完整执行。历史证据不足时标为“来源未核实”或仅标“Easy Ask AI”，不会凭回复里提到技能名就认定使用。

明确的小改不应被强制拉进长访谈。打开侧栏只读取原记录，不新建任务、不发送提示词、不生成答案或认可。历史回看采用原文关联，不调用额外模型替旧聊天编写结论；新的结构化理解由原聊天中的模型工具更新。普通回复本身可回看，是否需要澄清仍由当前模型判断。

### 先导出，稍后接着做

“记录与导出”中的“只导出当前版本”生成同一版的 `requirements.md`、`execution-prompt.md` 和 `start.txt`，不会创建会话或发送任务。导出放在新的版本目录，保留已有文件。修改导出后，用“导入人工文件”显式建立新版本，再核对条目与范围；导出文件本身不是执行认可。

## 准备一个新任务

在原聊天直接说出想法，例如：“我想做一个活动报名页，但内容和结构还没想好。请先帮我问清楚需求，整理可执行的方案，先不要制作页面。”需要澄清时，模型使用 Prompt Ready 流程，右栏显示紫色来源标签；你继续在原聊天回答，再核对报告。只想把要求交给另一个对话时，在“原作、版本与结果 → 记录与导出”中选择“只导出当前版本”，取得同一版的三个交接文件。导出不会创建会话或发送任务。本路径有代码与自动化检查，但没有报名页案例那样完整的真人业务验收。

## 没有开始提问时

先确认插件管理页已启用 Easy Ask AI DSH，且当前聊天属于已加入的工作区；“查看本次对话”应能打开右栏。若模型仍只给普通回答，可以在原聊天明确补充：“先用 Easy Ask AI 帮我问清楚这次需求，整理方案让我核对，先不要修改文件。”这会向原模型继续表达要求，不保证模型一定按同样方式提问。若已误改文件，插件没有自动回滚功能，应先在原聊天停止后续修改并核对文件，再处理恢复。

如果原来的 Easy Ask AI Skill 也已安装，可以保留；插件不会卸载或改写它，但不能保证模型同时使用两套入口时自动去重。首次单独验证插件时可以只启用本插件。右栏的“已读 Skill”仅说明读取过原 Skill 材料，Get Clear／Prompt Ready 的插件标签有单独的实际操作依据。

## 谁负责哪一步

| 参与者 | 负责的事 |
|---|---|
| 模型 | 阅读已提交材料、提出候选问题、整理需求、执行已认可范围、登记结果依据 |
| 使用者 | 回答真实想法、纠正理解、认可具体范围、查看并评价成果 |
| 插件 | 保存来源和版本、核对认可依据、冻结投递内容、保留回执与冲突 |

认可绑定报告版本、内容校验值和范围。V1 的认可不能授权 V2 新增的内容。若本插件能从官方会话日志核验同一工作区中的原始用户认可，便可沿用；模型传入“用户已经同意”不成立。插件只校验自己的提交路径，不能阻止你在其他聊天中直接发任务，也不能保证模型每次都问得合适。

## 数据、失败与卸载

- 需求真源保存在所选工作区的 `.prompt-ready/<任务标识>/eh3-easy-ask-ai/`。原作摘录、回答、报告、认可和执行快照会保留；可读导出在其版本目录中。备份时保留整个目录。
- Harness 插件存储保存索引、会话绑定和回执。侧栏历史加载和运行状态订阅针对当前选中且已打开侧栏的聊天，来源为 Harness 官方会话日志；纯历史视图只作内存缓存，关闭后可重新读取。已经接入需求流程的聊天会继续把后续真实用户消息同步到工作区记录，任务完成或关闭侧栏不会停止这项同步。停用插件后停止实时同步；重新启用并读取原聊天时可能补读历史。接入澄清后，模型通过工具读取本聊天历史及当前记录，包括原话、原作摘录、文件路径、版本及认可范围。这些内容进入 Harness 的官方会话，由你配置的模型服务处理。插件不读取模型账号密钥。选定摘录不限制模型依据 Harness 权限读取完整原文件；图片区域也不保证只上传裁切内容。
- 文本定位结合原文、上下文和文件校验值。文件改版后会提示核对，不能只凭旧行号继续指认。图片使用原图尺寸和归一化区域；网页摘录是获取时的快照。
- 普通文档保留文件和摘录引用，不内置 Word 编辑器。视频可以保存时间段及可选的 Media Review 任务引用，不依赖另一个插件运行。
- 保存冲突会保留你的输入；未取得回执时先核对记录，再用原操作重试。投递被会话受理不等于任务完成。已经受理的任务须在 Harness 会话中停止，插件里的取消只适用于尚未投递的执行包。
- 可在当前配置的插件管理页关闭或移除插件。需求、导出和结果文件会保留；重新安装后从工作区重新读取，不会自动重发旧任务。如确实不再需要，可先停用插件、备份后再删除相应任务目录。当前版本不会同时清除该任务在 Harness 插件存储中的聊天绑定；删除已绑定目录后，同一原聊天可能因记录缺失而无法打开或重新接入，需要恢复备份目录，或改用新聊天。重装插件不能恢复已删的文件。这只删除该目录中的本地记录，不会清除原作、另存的结果、Harness 的会话日志/插件存储或模型服务已经接收的数据。插件不提供跨这些位置的一键清除；其他记录须按 Harness 和所用模型服务各自的数据管理方式处理。
